# 同じ種類のグループの重複が、エラーではなく黙って落ちる

**状態:** 未着手。仕様と実装が食い違っている。

## 仕様が言っていること

`docs/spec/syntax.tmt:146`

```
@xxx()(){}{}[][]    // 複数括弧(同じ種類のグループの重複)はエラー
```

## 実際に起きること

```
@memo(a: 1)(b: 2)
→ <p><span class="tm-element tm-memo" data-a="1"></span>(b: 2)</p>
```

エラーにならない。2 つ目のグループは**地の文に落ち**、要素は行末で終わらなく
なるので `Placement::Block` から `Inline` に降格する。黙って意味が変わる。

`{}` でも同じ。

```
@memo{a: 1}{b: 2}   → a だけ
```

## 原因

`crates/tomet-syntax-parser/src/element.rs` の `parse_groups` は各スロットを
`Some('(') if el.args.is_none()` のようにガードしている。埋まっていれば分岐が
成立せず `_ => {}` に落ちてループを抜ける。カーソルは 2 つ目の `(` の手前に
残り、そこから先は地の文として読まれる。

つまり「重複を検出して拒否している」のではなく、「重複に気づかないまま解析を
やめている」。

## `:` との関係

`:` が「既に埋まったスロットにマージする」意味を持つのは、この捨てられ方の
裏返し。`@memo(a: 1):(b: 2)` は a と b の両方が入る。
→ `colon-as-sigil.md`

## 決めること

規範層 (`docs/spec/`) は作者のものなので、どちらに寄せるかは作者の決定。

- **実装を仕様に合わせる**（本当にエラーにする）。壊れる文書があるかは要走査。
  エラー位置は 2 つ目のグループの開き括弧。
- **仕様を実装に合わせる**（地の文に落ちる、と書く）。ただし「黙って
  ブロックからインラインに降格する」は仕様として書きたい挙動には見えない。

私見では前者。ただし `@memo()()` のような書き方に依存した文書が無いことを
確かめてから。
