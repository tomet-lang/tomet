## 3 → 2 にできる（挙動変更なし）

72 は `eat_list_marker_with_indent` の中で `found_group` を計算して**捨てている**。
114 は `parse_list_internal` で同じことを peek し直している。

**`found_group` を返り値に載せれば 114 は消える。** 今の返り値は
`(usize, bool, Option<Value>)`（indent, ordered, marker）で、ここに一つ足すか、
名前つきの構造体にする。挙動は変わらない。

残る 2 つは本当に別の問い:

- 55 はリストにしか無い（`@name` と `#` は args の前に名前か `#` の連なりが
  あるので、この曖昧さが発生しない）
- 72 は安い述語で、`Stop::Paragraph` の行ごとの先読みからも呼ばれる

## 同時に直したい非対称が 2 件

### 2a. `-(x)` 単体が項目にならない

```
#(id: a)      → <h1></h1>
@memo(x: 1)   → 要素
-(x)          → <p>-(x)</p>
```

原因は 72 の集合に `(` が無いこと。`sigil-follow-set.md` の `opens_group` に
置き換えると自動的に直る。

**リスク:** 地の文の行頭に `-(` が来ると項目になる。顔文字など。
着手前に `docs/` と `tests/fixtures/` を走査して件数を出すこと。

### 2b. `- (x)` のマーカーが文字列に落ちる

```
-(x)[ y ]   → マーカー x の項目
- (x)       → 内容が文字列「(x)」の項目
```

原因は 55。`(...)` の後ろに続いてよいものが「空白 / `[` / `{` / `|`」で、
**行末が入っていない**。probe が失敗し、`has_ws` のおかげで項目にはなるが
`(x)` は糖衣本文として文字列になる。`#(id: a)` が「args つき・内容空の見出し」に
なるのと食い違う。

修正は 55 の集合に行末を足すだけ。

**リスク: 2a より高い。既存文書の意味が変わる。** `- (注)` だけの行を書いていた
人は、内容が消えてマーカーになる。着手前に必ず走査すること。
