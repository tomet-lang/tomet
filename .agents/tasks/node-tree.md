## Decided (author, 2026-11-06)

- The levels are **Vault > Folder > File > Section**. They stay different things. Nobody is unifying them under `self.tmt`.
  - Vault: `vault.config.tmt` (unchanged; it is the vault's marker and its own heading part).
  - Folder: its entry file, `self.tmt` by default. Its leading `::` run is the Folder's heading part.
  - File, Section: as today.
- The entry file name is set per vault: `::workspace{ folder: { entry: self.tmt } }` in `vault.config.tmt`
  (vault-only, so one name for the whole vault). The tomet repo uses `self.tmt`. Default when unset: `self.tmt`.
- `.config.tmt` is **abolished** and absorbed into the Folder's entry file. One switch, no transition, no fallback read.
- **No backward compatibility, in any form**: no fallback to `.config.tmt`, no `tomet check` report about a leftover
  `.config.tmt`, no shim, no re-export. Renaming files is not `tandr`'s job (`tandr` edits contents only) and the
  repo has no `.config.tmt` to rename (checked 2026-11-06).
- `::` stays a File-only construct (`cotomet-syntax-and-data-modeling.tmt` §1). A Section has no declarations; do not
  add a `declarations` field to `Section`. `Header` in `tome.tmt` is a borrowed view for `tomet-tome` at most, never an AST type.
- Which declarations a Folder's entry file passes down to its descendants: **exactly what `.config.tmt` passes today**
  (the config layer merge, `Config::from_layers`). Widening to `::kind` / `::rule` etc. is a later decision.
- Not now (author): Folder addressing, child ordering (collation order, `self.tmt` may state it explicitly -- later),
  anything about `Header`.

Design as agreed (2026-11-06):

Design (agreed):
- Pure, in-memory crate `crates/tomet-tome`, **layer 6** (like `tomet-vault`; no disk). Depends only on `tomet-ast`,
  `tomet-tree`, `tomet-span`, `tomet-sort`. It knows no config type: the entry name is a `&str` argument.
- `.writ.tmt`: add `"crates/tomet-tome"` to layer 6 plus a "listed by name" paragraph. **The author's file: propose, never edit.**
  Proposal to give the author at the end (text of the paragraph: pure in-memory assembly of parsed documents into the
  Vault > Folder > File > Section tree; its name shares no prefix with the existing groups).
- Model: `Tome` owns the tree. `Vault { config file (File), root: Folder }` -- **the vault's root directory is a Folder like any
  other** (root `self.tmt` = its entry). `Folder { entry: Option<File>, children: Folder | File }`. Files are the parsed
  `tomet_ast::File`; a Section is **not copied**, it is a borrow into its File's AST.
- Traversal: borrowed enum `tomet_tome::Node<'a>` (Vault, Folder, File, Section) -- same name as `tomet_tree::Node`, told apart
  by module (author agreed). One `children()` and one `walk()`, the single place that says what is in what (as `tomet-tree` does).
- Heading part: borrowed view `Heading<'a>` (`declarations`, `title`, `data`, `id`, `connects`); Vault = config file's `header`,
  Folder = entry's `header`, File = `header`, Section = no declarations. **Never an AST type; no `declarations` on `Section`.**
- Building (pure): input = entry name + `(relative path, parsed File)` list + the vault config file. Group by directory; the file
  named as entry is the Folder's entry, not a child; a Folder without an entry has an empty heading part; children in collation
  order (`tomet-sort`). Explicit order in the entry is later (not now).
- Disk side: `tomet-load` gets `Vault::tome()`, using `tomet-indexer`'s collection and its `ignore`/`unswept` rules; `.ctmt` is
  not part of it. (`unswept` files are in the tree; `ignore`d ones are not.)
- Not now: Folder addressing, explicit child order, moving config layering into the Tome, joining the tree into one document
  (Step 4), CLI.
